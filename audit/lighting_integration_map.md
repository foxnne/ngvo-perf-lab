## 3. Symptoms a-g

**a. Sun/moon rays never appear.** Correct. `DrawSunRays` exits at `Effects11.cpp:1370-1372` unless Effects 11 is the active pipeline or `settings.StandaloneRays` is true (default false, `Effects11.h:184`; no Effects11 block in SettingsUser.json). It also needs `EffectManager` initialised (`:1389`) *(not verified that this holds under the Post Processing pipeline)*. Fix: set `StandaloneRays` true; then apply S8 so rays respect volumetric clouds and use the simulated sun.

**b. Stepped shadow in haze.** Suspicion right, with two additions (S3 and the unjittered XY sample).
- Grid sizing (`ViewAtmosphere.cpp:189-226`): cells = ceil(renderW / pixelSize) x ceil(renderH / pixelSize) x slices; near 16 px x 64 slices to `nearRange` 8000 units (114 m); middle 64 px x 32 slices to `localRange` 60000 units (857 m); distant 32 px x 64 slices to 40 km. Exponential slices (`ViewAtmosphere.hlsli:47-55`). All three share one RGBA16F atlas capped at 8M texels.
- Injection: one sample per cell; Z jittered when temporal AA is on; XY jittered only by `sampleJitter` (0) (`LightScattering.cs.hlsl:168-172`). Shadows are hard (cascade 2x2 gather, terrain height test, `:34-49`).
- Temporal: reprojected history, weight 0.96, reduced on extinction change (`:205-217`); reset when shadow inputs change (`ViewAtmosphere.cpp:298-303`).
- Upsample: hardware bilinear in XY inside the atlas, analytic interpolation between integrated slices in Z; no depth-aware filter, no lookup jitter (`ViewAtmosphere.hlsli:125-163`).
- Why middle is coarser than distant: not stated in code. *(inferred)* The middle grid is the old volumetric-fog "far" grid (`src/Features/ExponentialHeightFog.h`, `farGridSizeAndFlags`: "continues from the near grid to the shared local range") where local-light fog is expensive and low-frequency; the distant grid carries horizon terrain silhouettes at small angular size, so it got finer cells. With volumetric fog off this reasoning no longer applies.
- A mountain beyond 857 m: its haze shadow lives in the middle and distant grids, i.e. 64 and 32 px cells.
- Cheapest fix, in order: (1) `sampleJitter` 1.0: no extra cells, turns the per-cell binary shadow into a temporally integrated coverage; (2) `middlePixelSize` 32: at 2560x1440 render that is 29k -> 115k cells against 0.92M near and 0.23M distant, about +7% of injected cells *(computed, render size assumed)*; (3) `distantPixelSize` 24 if still visible (+0.18M cells, +15%); (4) S3: with the sun under 7.2 deg the shadow plane is not where the sun is, so lower `MinShadowElevation`.
- Jitter risk: more noise under fast camera motion; keep `historyWeight` 0.96.

**c. No shafts through cloud gaps.** The cloud term is present in the froxel path and correctly weighted (`LightScattering.cs.hlsl:56-62`: direct in-scatter x shadow-volume transmittance; remap 0..1 is identity). The UI hint is accurate: `ApShadow.hlsli` (30-step per-pixel march) only runs in the fallback (`PhysicalSky.cpp:2229-2230`, `Volumetrics.cs.hlsl:1477-1481`). Shafts are missing because:
1. S1: the local shadow volume covers +-4 km and returns the mean whenever the light path leaves the box, which is always the case below ~13 deg sun elevation with the live cloud layer. The froxels then receive one uniform number.
2. Distant grid cells are 32 px wide with one unjittered sample (S2); gap-sized beams at 3-10 km are under-sampled.
3. Contrast is diluted by unshadowed terms: the MS-LUT term uses only the mean `GetCloudDiffuseTransmittance` (`LightScattering.cs.hlsl:60,160`), and the weather fog ambient term is unshadowed (S10).

What makes them visible: `shadowVolumeRange` 16; `sampleJitter` 1; `distantPixelSize` 16-24; S10; then the far-field shadow map code change in S1 for shafts at the horizon and at low sun.

**d. Game god rays ignore volumetric clouds and the simulated sun.** Right (S7). They are a second implementation of what the near froxel grid already does with cascade shadows. Recommended: turn exterior Volumetric Lighting off after S2; if the look is wanted, patch line 104 of `ISVolumetricLightingGenerateCS.hlsl`.

**e. Mountain cloud meshes lit differently.** `cloudRelightMix`, `cloudOriginalMix`, `silverLining*`, `enableVanillaClouds` act only on sky-dome cloud layers (`Sky.hlsl:403-406`); `vanillaMix` only on the sky gradient (`Sky.hlsl:531`). The meshes are `Effect.hlsl` and only see `lightSkyStatics` / `skyStaticsBrightness` (`:1020-1029`). Differences vs volumetric clouds: S-SCENE vs S-TOA (S4), weather ambient vs sky SH, no phase function, no 2.58 brightness scale. Fix order: S4 first (removes the largest gap at low sun); then code in `Effect.hlsl:1020-1029`: ambient from `ImageBasedLighting::GetSkyIBLColor(up)` instead of `GetAmbientLighting`, sun term x a forward/back phase blend and the cloud `lighting.brightness`. Alternative with no shader work: replace the meshes with PS local clouds (`cloudMap.localCloud`) and hide the meshes.

**f. Pale tan sunsets, white glow, dark neutral ground.**
- Ground dark: S4 (Sky Sync dim x physical Tr), S5 (EHF attenuation), S6 (double cloud shadow); LL `directionalLightMult` is the only compensator. Auto exposure meters a frame dominated by the bright sky, so the ground falls further.
- Ground neutral: S9 (weather DALC + 0.6-saturation sky SH).
- Pale/tan sky and white glow: S13 grey heavy aerosol (39.96 Mm^-1, more than twice Continental at 50% RH, `AerosolData.inl:6`), forward phase g 0.8; S10 weather-coloured fog in the same froxels; the ~26,000-unit sun disc feeding COD Bloom (threshold 2.14, `BlendFactor` 0.15) *(inferred: bloom not read)*; post saturation 0.80 in the baseline grade.
- Owners after the fix: sun colour/intensity = PS (`sunlightColor`, Tr); horizon fade = Tr only; ambient = sky SH; fog colour = sky IBL; exposure = Histogram AE.

**g. Cost.**
- Not duplicated today: EHF standalone volumes are released (`ExponentialHeightFog.cpp:789-794`), `AccumShadow` is skipped, AP LUT is still generated for reflections (32^3, small).
- Duplicated: game volumetric lighting (generate + 2 blurs + apply; baseline custom size 288x256x130 if quality is Custom) vs near froxel grid (S7); Cloud Shadows cubemap layer passes for hidden vanilla layers (S6/S12).
- Volumetric clouds ~5 ms: live `rayMarchRange` 41 km (default 32) and `marchStepScale` 0.5; each `RenderVolumetricClouds(kMainViewAndCubemap)` also updates the cube, ambient transport and lightning. Knobs: `rayMarchRange` 32, `marchStepScale` 0.75-1.0. *(pass costs not measured here)*
- SSGI 5.6 ms: independent of the atmosphere stack; not audited in depth. It supports half/quarter-res tracing (`src/Features/ScreenSpaceGI.h:78-79`).
